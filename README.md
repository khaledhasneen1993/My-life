# My-life — Final-3 Pro المعتمد

النسخة المعتمدة الوحيدة هي `final3_pro.py` على فرع `main`، وتشمل Tight Stop والتعادل الشامل للرسوم والإغلاق الجزئي بعد التعزيز. البوت كامل في ملف Python واحد؛ لوحة التحكم المشتركة إضافة اختيارية في مجلد `dashboard`.

## الإعدادات

| الإعداد | القيمة |
|---|---|
| رصيد جديد | 100 USDT افتراضي |
| هامش الدخول | 10%، يزيد خطيًا بعد قوة 0.09 حتى 17% عند قوة 0.18 |
| الرافعة / المراكز | 50× / خمسة مراكز كحد أقصى |
| التعزيز | مرة عند انعكاس 2.5% من الدخول الأول، بنفس القيمة الاسمية تقريبًا بعد تقريب الكمية |
| الهامش | يُرفض الدخول أو التعزيز إذا لم يكف المتاح للهامش والرسوم |
| الوقف الأولي | 7% من الدخول الأول |
| الوقف بعد التعزيز | 4% من متوسط الدخول الجديد، مع الحفاظ على أي وقف أقرب |
| الإغلاق الجزئي | 50% من الكمية مرة واحدة عند انعكاس 3% من المتوسط بعد التعزيز |
| وقف التعادل | يُفعّل بعد تعافي السعر وتجاوزه المستوى الذي يغطي الرسوم والخسائر الجزئية المحققة |
| التريل | يتفعل عند ربح 1.8% من المتوسط، بمسافة 0.9% من أفضل سعر |
| مراقبة الخروج | مهمة مستقلة كل 8 ثوانٍ |
| حداثة السعر | رفض التنفيذ إذا غاب توقيت التيكر أو تجاوز فرق التوقيت 12 ثانية |
| المسح | أعلى 40 عقدًا مؤهلًا، ثم انتظار 600 ثانية بعد كل دورة |
| الرسوم | 0.05% لكل تنفيذ |
| الحالة المطبوعة | كل 30 ثانية، مع آخر ثلاثة تنفيذات |
| ملف الحالة | آخر 150 تنفيذًا، مع الرصيد والمراكز وبيانات استئناف الحماية |

معادلة الحجم: `margin_pct = 0.10 + 0.07 * min(1, max(0, (strength - 0.09) / 0.09))`.

شروط الإشارة: حركة تتجاوز ±1.2%، وحجم يتجاوز 3.5 أضعاف المتوسط، وعدم توازن دفتر الأوامر يتجاوز ±0.35، وحجم تداول يومي لا يقل عن 15 مليون USDT. انحياز 5 دقائق المتوافق يرفع قوة الإشارة 12%.

## حماية المراكز

الوقف يتحرك باتجاه تقليل المخاطرة فقط. إغلاق النصف يحرر الهامش بنسبة الكمية المغلقة، ويُحفظ لمنع تكراره بعد إعادة التشغيل. إذا تعذر تقسيم الكمية بعد التقريب يبقى المركز تحت الوقف الكامل ويظهر السبب في السجل.

إذا قفز السعر متجاوزًا الوقف، يكون إغلاق المتبقي كاملًا قبل الإغلاق الجزئي. الأسعار هي المتاحة وقت الفحص؛ زمن الشبكة وانتظار القفل قد يؤخران دورة المراقبة.

التعادل يشمل رسوم الدخول والتعزيز والإغلاق الجزئي والإغلاق المتوقع للمتبقي، إضافة إلى الخسائر المحققة من الإغلاق الجزئي. يبقى التريل فعالًا وقد يبدأ قبل تعادل المركز كاملًا بعد إغلاق جزئي خاسر. الوقف لا يضمن التنفيذ عند مستواه عند القفزات.

أسباب التنفيذ: `SL` للوقف الأولي، `TIGHT_SL` للوقف الأضيق، `BE_SL` للتعادل، `TRAIL_SL` للتريل، و`PARTIAL_RISK` للإغلاق الجزئي. يسجل الإغلاق النهائي `position_net_pnl_usdt` لصافي المركز كاملًا؛ `pnl_usdt` يخص كمية التنفيذ قبل رسمه.

## تشغيل البوتات الثلاثة بلوحة واحدة

لتشغيل **Final وFinal-3 وMy-life** معًا، أوقف أي محاكاة أو لوحة قديمة، ثم من مجلد My-life:

```bash
bash run_dashboard.sh
```

لبداية جديدة للثلاثة برصيد **100 USDT لكل بوت وصفر صفقات ومراكز** استخدم `bash run_dashboard.sh --fresh`. التشغيل التالي دون `--fresh` يستأنف الجلسة الجديدة نفسها.

افتح `http://127.0.0.1:8787`. تعرض اللوحة الحسابات والمراكز والتنفيذات والإغلاقات الجزئية وأسباب الخروج، مع تشغيل وإيقاف وتصدير CSV وJSON لكل بوت أو للجميع. تستأنف الملفات السابقة وتطبع مساراتها وأرصدتها قبل التشغيل، وتبدأ الحسابات المفقودة فقط بـ100 USDT. يُحفظ أرشيف دائم للتنفيذات المتاحة والجديدة مستقل عن نافذة 150 تنفيذًا. [التعليمات الكاملة](dashboard/README-AR.md).

## التثبيت

Python 3.11 أو أحدث، داخل أوبونتو في تيرمكس:

```bash
cd /root
git clone https://github.com/khaledhasneen1993/My-life.git
cd My-life
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final3_pro.py
```

## تحديث نسخة موجودة

أوقف البوت بـ Ctrl+C وانتظر رجوع المؤشر، ثم:

```bash
cd /root/My-life
git pull --ff-only
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final3_pro.py
```

شغّل عملية واحدة فقط على ملف الحالة نفسه. التحديث في Git لا يغير عملية جارية تلقائيًا.
