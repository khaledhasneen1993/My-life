# لوحة Final وFinal-3 وMy-life

اللوحة المحلية تشغل ثلاث عمليات مستقلة من مصادر Git الأصلية. My-life يحتفظ بمنطق Tight Stop والتعادل والإغلاق الجزئي؛ Final وFinal-3 يحتفظان بإعداداتهما الأصلية. لا تشغّل Final-2.

## التشغيل

أوقف أي بوت أو لوحة قديمة بـ Ctrl+C أولًا، وانتظر رجوع المؤشر. داخل أوبونتو في تيرمكس:

```bash
cd /root/My-life
git pull --ff-only
bash run_dashboard.sh
```

افتح `http://127.0.0.1:8787` من متصفح الهاتف. المشغل يجلب أو يحدث مصادر Final وFinal-3 بتحديث fast-forward، ويثبت المتطلبات في بيئة مستقلة. يرفض الكتابة فوق مصدر به تعديلات محلية. يعمل البوتات الثلاثة تلقائيًا؛ خيار `--no-autostart` يفتح اللوحة دون تشغيلها.

Ctrl+C يوقف الثلاثة ويحفظ الحسابات. أزرار اللوحة تتحكم بكل بوت على حدة أو بالثلاثة. الإيقاف يحفظ المراكز المفتوحة لكنه يوقف مراقبتها حتى الاستئناف، ولا ينفذ إغلاقًا تلقائيًا لها.

## بداية جديدة للثلاثة من الصفر

بعد إيقاف اللوحة القديمة بـ Ctrl+C وتحديث My-life:

```bash
bash run_dashboard.sh --fresh
```

ينشئ هذا الخيار مجلد جلسة جديدًا فريدًا تحت `.runtime/sessions/`، مع ثلاثة ملفات حساب مستقلة وأرشيف ومنحنى جديدين. يبدأ كل بوت برصيد 100 USDT وصفر صفقات وصفر مراكز؛ فلا يحمل أرصدة أو تنفيذات الحسابات السابقة. يطبع المشغل المسارات والأرصدة قبل التشغيل.

بعد ذلك، يكفي `bash run_dashboard.sh` دون `--fresh` لاستئناف الجلسة الجديدة نفسها. استخدام `--fresh` مرة أخرى يبدأ جلسة أخرى من الصفر. تُحفظ الجلسات القديمة في أماكنها للمراجعة.

ملفات حسابات الجلسة الجديدة تكون `data/final.state.json` و`data/final3.state.json` و`data/mylife.state.json` تحت مجلد الجلسة المطبوع، وتظهر المسارات الفعلية في تبويب الإعدادات. استخدم تصدير اللوحة للحصول على تقارير الجلسة الحالية بدل نسخ الملفات الافتراضية القديمة.

## الحفاظ على الحسابات

- عند أول تشغيل عادي، قبل إنشاء أي جلسة جديدة: My-life يستأنف `/root/My-life/paper_state_final3_pro.json`.
- Final-3 يستأنف ملف `paper_state_final3.json` من مستودع Final-3 الموجود بجانب My-life إن وجد؛ وإلا يستخدم المصدر الذي جلبه المشغل داخل `.runtime/repos/Final-3`.
- Final يستأنف `data/final.state.json` من مسار التشغيل المسجل سابقًا في `Final-3/.runtime/account-location`، ويستخدم مسار `/root/cascade-termux/data/final.state.json` إن وُجد عند غياب ذلك السجل. إذا لم يوجد مسار سابق، يبدأ حسابًا في مجلد تشغيل اللوحة الجديدة.
- يبدأ الحساب المفقود بـ100 USDT. لا يمسح المشغل حسابًا قائمًا ولا يعيد الرصيد إلى 100.
- يطبع المشغل المسارات والأرصدة وعدد المراكز والتنفيذات قبل التشغيل؛ وتعرضها اللوحة في قسم الإعدادات.
- ترحيل إعداد Final-3 القديم إلى وقف 7% يتم بآلية المستودع الأصلية مع نسخة احتياطية، وفقط إن كان بلا مراكز مفتوحة. إن كان الترحيل مطلوبًا مع مراكز مفتوحة يتوقف التجهيز.

لتحديد المسارات صراحة يمكن ضبط هذه المتغيرات في كل تشغيل:

| المتغير | الوظيفة |
|---|---|
| `CASCADE_RUNTIME_DIR` | مجلد اللقطات والسجلات والأرشيف ومنحنى المحفظة |
| `CASCADE_FINAL_DIR` | مصدر Final |
| `CASCADE_FINAL3_DIR` | مصدر Final-3 |
| `CASCADE_FINAL_STATE` | ملف حساب Final |
| `CASCADE_FINAL3_STATE` | ملف حساب Final-3 |
| `CASCADE_MYLIFE_STATE` | ملف حساب My-life |

يحفظ المشغل مجلد التشغيل ومسارات ملفات الحسابات الثلاثة في `.runtime/dashboard-accounts.json`، ومجلد التشغيل أيضًا في `.runtime/dashboard-location`. التشغيل العادي يستأنف آخر اختيار محفوظ. المتغيرات الصريحة تتجاوز الاختيار المحفوظ، وتغيير مجلد التشغيل إلى مجلد آخر يعيد استخدام قواعد المسارات الافتراضية ما لم تحدد ملفات الحسابات صراحة. يجب أن تختلف ملفات الحسابات الثلاثة.

لا تشغّل بوتًا يدويًا بجانب اللوحة على الحساب نفسه. أقفال ملفات الحالة تمنع العمال المكررين والمشغلات التي تحترم هذه الأقفال؛ لا تمنع إصدارات قديمة لا تستخدمها. بدء لوحة ثانية على المنفذ 8787 يُرفض.

## السجل الكامل والتقارير

تحتفظ اللوحة بأرشيف SQLite مستقل لكل بوت وملف حساب، داخل مجلد تشغيلها، وتلتقط التنفيذات عند حدوثها. تُستورد جميع التنفيذات المتاحة في الحالة عند أول تشغيل، وتُحفظ التنفيذات الجديدة حتى إن كانت حالة My-life تحتفظ بآخر 150 تنفيذًا فقط. لا يمكن استرجاع تنفيذات سبق حذفها قبل أول تشغيل للوحة.

الإغلاق الجزئي يظهر كتنفيذ مستقل `PARTIAL_RISK`، ولا يُحسب إغلاقًا نهائيًا. تُغلق الصفقة في الإحصاءات بعد إغلاق الكمية كلها، ويشمل صافيها الأرباح والخسائر الجزئية ورسوم جميع التنفيذات. السجل الناقص يظهر بتنبيه ويُستبعد من إحصاءات الصفقات المكتملة، وتبقى كل تنفيذاته متاحة للتصدير.

يمكن البحث بالعملة وتصفية البوت، وتنزيل CSV للتنفيذات أو الصفقات المكتملة لكل بوت أو للثلاثة. تقرير JSON يشمل الحسابات والمراكز والإعدادات والتنفيذات والسجلات. أمثلة:

- `http://127.0.0.1:8787/export/all/snapshot`: تقرير الثلاثة JSON.
- `http://127.0.0.1:8787/export/mylife/fills`: جميع تنفيذات My-life بصيغة CSV.

حافظ على مجلد التشغيل والأرشيف مع ملفات الحالة عند النقل إلى جهاز آخر. حذف الأرشيف يزيل السجل الذي تجاوز نافذة ملف الحالة. منحنى المحفظة يحتفظ بآخر 30 يومًا؛ أرشيف التنفيذات لا يُحذف تلقائيًا.

## حالة البيانات

Final وFinal-3 يستخدمان WebSocket مع عرض حداثة كل عملة. My-life يستخدم REST؛ تعرض اللوحة عمر التيكرات المرصودة وفحص 12 ثانية، ولا تصف اتصاله بأنه WebSocket. بقاء العملية تعمل أو اتصال اللوحة لا يثبت وحده حداثة بيانات السوق.

## التحقق

```bash
.venv-dashboard/bin/python -m unittest discover -s dashboard/tests -v
.venv-dashboard/bin/python -m compileall -q dashboard final3_pro.py
```

اختُبرت الواجهة البرمجية والتصدير والأرشفة والإغلاق الجزئي واستقلال الحسابات ببيانات وهمية. لم يُشغل التداول على سوق حي ضمن التجهيز. أندرويد قد يوقف تيرمكس في الخلفية؛ استمرار المحاكاة يعتمد على استمرار العملية واتصال الهاتف. المحاكاة تستثني التمويل والتصفية والانزلاق.
